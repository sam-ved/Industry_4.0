PROJECT HANDOVER & FINAL REVIEW INTELLIGENCE
============================================

1. PROJECT IDENTITY
-------------------
* Project Title: Industry 4.0 AI Control Center (also referred to as ML Studio (Self-Training) / Fine-Tuning Studio in self-training contexts).
* Project Type: Industrial AI, Computer Vision, Predictive Maintenance, Energy Analytics, Digital Twin simulation, AutoML, and Decision-Support (Reasoning AI) Platform.
* Core Objective: To provide a unified, enterprise-grade control center that integrates edge computer vision, time-series telemetry analysis, physical digital twin simulations, and custom AutoML workspaces with a multi-model reasoning system. It provides factory operators, safety officers, reliability engineers, and plant managers with real-time anomaly alerts, predictive failure timelines, safety audits, and automated recommendations explaining why decisions are made.
* Target Users: Plant Managers, Reliability Engineers, Safety Auditors, Energy Management Consultants, and Industrial Data Scientists.

2. PROBLEM STATEMENT
--------------------
Modern manufacturing plants generate massive, siloed streams of multimodal data (high-speed camera feeds of steel sheets, CCTV feeds of personnel zones, grid/solar power meters, and rotating machinery sensors). However, they lack a unified system that can:
1. Bridge the multimodal gap: Simultaneously run visual object detection (defect/safety) and telemetry-based forecasting (energy/downtime).
2. Mitigate black-box predictions: Provide physical and operational explanations for why a machine has a low remaining useful life (RUL) or why energy consumption spiked.
3. Empower non-technical operators: Allow users to train custom models (AutoML/fine-tuning) on their own CSV/image datasets without writing Python training scripts.
4. Coordinate multi-model consensus: Fuses predictions from different models (e.g. classifier anomaly flag vs regression prediction) and resolves conflicting outputs.

3. OBJECTIVE
------------
The primary objective of the Industry 4.0 AI Control Center is to build a centralized, dark-themed control system that integrates four distinct core modules, a digital twin simulation engine, and an AutoML/fine-tuning dashboard. The system must process real-time uploads (images, videos, CSV data), execute real-time local machine learning inference (via YOLOv8, XGBoost, and scikit-learn models), and output automated, rule-based, and LLM-enhanced narrative reports containing clear root causes, operational risks, and step-by-step remediation plans.

4. PROPOSED SOLUTION
--------------------
The platform implements a multi-tier solution:
1. Multimodal Core Modules:
   * Steel Defect Detection: Detects surface defects (scratches, dents, cracks, corrosion) on steel sheets using YOLOv8 models.
   * PPE Compliance Monitor: Audits workers for safety equipment compliance (helmets, vests, gloves, boots) using YOLOv8-based object detection.
   * Energy Analytics: Inspects energy consumption profiles and flags anomalies using Random Forest models and IQR filters.
   * Predictive Maintenance: Predicts fleet health scores, remaining useful life, and anomaly statuses using XGBoost models and Isolation Forest classifiers.
2. Digital Twin Scenario & Simulation Engine: A physical scenario simulator that models production growth, machine efficiency, renewable energy mix, shift planning, demand forecasts, carbon footprints, cost optimization, and capacity constraints using a customized physics/formula engine, sensitivity analyzers, and Monte Carlo runs.
3. AutoML Tabular Studio: A wizard allowing users to upload tabular CSV files, select target variables, automatically profile data quality, get heuristic-based feature suggestions, and train/compare multiple algorithms (Random Forest, Gradient Boosting, Linear/Logistic Regression, KMeans) in parallel.
4. Custom YOLOv8 Fine-Tuning Studio: A self-training workspace where users can upload custom annotated object detection datasets and queue training runs (using PyTorch and CUDA) in the background via Celery and Redis.
5. AI Decision Intelligence Reasoning Layer: A multi-step processing engine that parses model outputs, evaluates deterministic rules, calculates consensus among models, computes a fused confidence score, infers root causes, and generates actionable, priority-sorted recommendations, which are then summarized into a natural narrative by a Groq-hosted Llama-3.1-8b-instant LLM.

5. SYSTEM OVERVIEW
------------------
* User Interaction:
  1. The user logs into the dark-themed dashboard showing KPIs, active alert streams, overall system health status, and module cards.
  2. The user navigates to a module and uploads files (e.g., steel sheet images, worker CCTV snapshots, plant electricity CSVs, or predictive maintenance telemetry).
  3. The system performs real-time file validation (verifying sizes under 10MB/50MB and matching extensions).
* Data Flow:
  [User File Upload] (Image/CSV)
        ↓
  [API Layer / Route Handlers] (FastAPI)
        ↓
  [Validation & In-Memory Dataset Cache]
        ↓
  [Pre-processors] (StandardScaler, LabelEncoder, OneHotEncoder)
        ↓
  [ML Models / Inference Engines] (YOLOv8 ONNX/PyTorch, XGBoost pkl, RF pkl)
        ↓
  [Analytics Algorithms] (Isolation Forest, IQR Spikes, Linear Degradation)
        ↓
  [Reasoning Layer Orchestrator]
     ├── 1. Evidence Collector (Stitch standard ModelFinding payloads)
     ├── 2. Rule Engine (Evaluate compliance, defect rates, temperature limits)
     ├── 3. Consensus Engine (Assess model agreement, highlight conflicts)
     ├── 4. Confidence Engine (Fuse model confidence with dataset constraints)
     ├── 5. Root Cause Engine (Deduce operational failures and parameters)
     ├── 6. Recommendation Engine (Generate prioritized action checklists)
     └── 7. Report Generator (Build structured Markdown/JSON reports)
        ↓
  [LLM Enhancer] (Groq Llama-3.1-8b-instant API) ──> (SQLite MD5 Hashed Cache)
        ↓
  [Frontend UI View & Exporter] (Interactive plots, Recharts, PDF/DOCX/Excel/CSV downloads)

28. LIKELY REVIEW QUESTIONS & ANSWERS
-------------------------------------
* Q: How do you prevent Uvicorn port conflict crashes?
  - Answer: We added a socket connection check in main.py that verifies port 8000 is open. If the port is occupied, it logs a warning message and exits gracefully.
* Q: How does the frontend handle backend offline states?
  - Answer: The useBackendStatus hook polls the health endpoint every 3 seconds. If the request fails, the status badge turns red and upload actions are disabled.
* Q: How does the AutoML Studio train models in parallel?
  - Answer: The backend splits the dataset, runs preprocessing, and trains the models in parallel threads using Python's ThreadPoolExecutor.
* Q: What LLM provider is integrated, and how are API costs managed?
  - Answer: We query the Groq API using the AsyncGroq client and the llama-3.1-8b-instant model. To minimize API costs, we cache responses in the SQLite model_cache table.
